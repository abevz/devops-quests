v1.4.0 rewrites how all 130 quests present the task and judge the result: you get the goal, find the cause yourself and are checked on the outcome, not on one exact way to write it.

- Every quest has a short brief that states what must be true, where and with which supplied files, without giving away the cause or the fix. Live objectives list each condition separately (dq-21, dq-22, dq-24 and dq-15).
- The "Verify yourself" block is gone. Hints form a ladder: the mechanism first, then where to look, then how to check. Results are described by difficulty level (dq-57 and dq-17).
- Conditions that are already true at the start and must stay true are listed separately under Keep and only turn red when broken; goals no longer appear completed before you act (dq-78).
- Checks accept equivalent correct solutions in every track: selection by name instead of position, parsed quantities, percentages where counts are allowed and observed effects instead of exact command text (dq-32 via dq-68, dq-69, dq-70, dq-71 and dq-72; dq-73).
- Checks observe the result instead of hidden file structure, and a failed check names the condition that is not met (dq-76). Quest 102 waits briefly for the Service to switch to the new version instead of failing right after rollout (dq-83).
- Kubernetes manifests in `~/quest` are YAML. Quests 117 and 123 read the YAML you edit (dq-40).
- The quest page: Brief text can be selected and copied while objectives refresh (dq-77); play mode can be chosen on the quest page itself (dq-79); hints opened before Run show their cost, and a passed quest shows a clearly named debrief (dq-80); launch details are folded behind "What will start", with play time and sandbox type always visible (dq-81).
- English is the source language for guides; translations follow it (dq-20). CI and delivery process changes (dq-30, dq-31, dq-39, dq-43, dq-44 and dq-49).

Known issues: in some quests hint 2 still contains most of the diagnosis rather than only where to look; in multi-stage quest 130 the hint order does not follow the stages. Findings from the ongoing owner playtest are planned for the next release.

No database schema migration is included. Accounts, progress, pending briefing hints and saved Lab files are preserved. Deployments refuse active attempts, pending briefing hints and active or incompatible saved Labs. The previous release remains available for rollback through the documented operator procedure. Sandbox image inputs are unchanged; the CI Python wheelhouse moved to the `deps-2` snapshot (adds pytest-xdist).
