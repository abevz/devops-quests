Опубликованный релиз не дошёл до работающего приложения через существующий приёмник событий. Восстановите цепочку доставки, сохранив идентичность приложения, нагрузки и публикации, а также исходную программу.

Работайте в `~/quest`. Исходные записи описывают доверенный источник и защищённую публикацию; замороженные копии в `/run/dq/facts/0/` остаются авторитетными. Сохраните исходные идентичности, программы, границы доступа и доверие TLS. Не выводите учётные данные и не заменяйте защищённый источник.

Входы: `platform.env`, `webhook.env`, `hook-id`, `release-commit`, `repository/`, `application.yaml` и `webhook-publication.json`. Все активные принадлежащие нагрузке pod должны принять утверждённую публикацию Git с сохранением исходных ConfigMap, контроллера, ссылки на источник только для чтения и спецификации pod. Текущий приём события не гарантирует будущую доставку.

**Требования:**

- Существующий push hook репозитория активен для `main` и направлен на предназначенный приватный приёмник событий.
- Опубликованная `origin/main` совпадает с `~/quest/release-commit` на workstation и является новым потомком существующей истории репозитория.
- Application `board` сохраняет предоставленный приватный источник Git, ветку релиза и существующий каталог нагрузки.
- Application `board` сообщает `Synced` и `Healthy` для коммита из `~/quest/release-commit` на workstation.
- Deployment `board` завершает rollout в namespace песочницы.
- Исходная нагрузка и активный принадлежащий ей pod сохраняют идентичность, программу и источник только для чтения; согласованный ConfigMap и HTTP-ответ приложения соответствуют утверждённой публикации Git.
- Приватный приёмник принял аутентифицированное событие `main` из предоставленного репозитория.
